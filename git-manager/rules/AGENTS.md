# Git 操作安全规范

在为当前工作区执行任何 Git 命令或协助用户进行版本控制时，必须遵守以下安全规范：

1. **禁止未确认的破坏性操作**：
   - 严禁擅自执行 `git push --force`、`git push -f`、`git reset --hard`、`git clean -fd`、`git checkout -- .` 或强制删除未合并分支（`git branch -D`）。
   - 若确实需要覆盖远端历史，必须先向用户说明风险并获得明确二次确认，且优先使用更安全的 `git push --force-with-lease`。
2. **提交前核查**：
   - 提交前先检查 `git status` 与变更清单，留意是否误包含了 `.env`、私钥（`*.pem`、`*.key`）、凭据文件或大体积临时产物；若发现疑似敏感文件，停止自动暂存并提醒用户。
3. **非交互与中文路径兼容**：
   - 执行 Git CLI 时尽量避免触发交互式编辑器或终端提示（例如使用 `-m` / `--no-edit`、`GIT_TERMINAL_PROMPT=0`），处理含中文路径时注意不要依赖转义输出。
4. **失败透明**：
   - 当拉取、变基或推送失败（如合并冲突、non-fast-forward、未配置远端）时，直接展示真实状态与受影响文件，不要强行覆盖。
